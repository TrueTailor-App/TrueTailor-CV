# TrueTailor CV

כלי בקובץ HTML יחיד שמתאים קורות חיים קיימים למודעת דרושים ספציפית. רץ כולו בדפדפן, בלי שרת ובלי build step. הקריאות היחידות החוצה הן ל־Google Gemini API עם מפתח שהמשתמש מספק.

גרסה נוכחית: **v35.6**

- אתר חי: https://truetailor-app.github.io/TrueTailor-CV/
- מאגר: https://github.com/TrueTailor-App/TrueTailor-CV

## מפת הקבצים

| קובץ | תפקיד |
|---|---|
| `index.html` | האפליקציה שרצה באתר החי. 11,992 שורות, `TT_VERSION` בשורה 1530. זה הקובץ ש־GitHub Pages מגיש. |
| `TrueTailor_CV_v35_5.html` | הגרסה הקודמת, v35.5. נשמרת כנקודת נסיגה. |
| `update_site.bat` | מעתיק גרסה ממוספרת על `index.html`, מוודא אותה, ודוחף ל־GitHub. |
| `TrueTailor_CV_Project_Dossier.md` | תיק הפרויקט. ארכיטקטורה, עקרונות מוצר, מודל נתונים, יומן גרסאות, פערים ידועים. נועד להיטען ל־Project Knowledge. |
| `TrueTailor_CV_Project_Instructions.md` | הוראות התנהגות למודל. נועד להדבקה בשדה Instructions של הפרויקט. |

בשורש המאגר יושבים גם `TrueTailor_CV_v25*.html` (תשעה קבצים), `TrueTailor_CV_v27.html` ו־`TrueTailor_CV.zip`. אלה שאריות מגרסאות קודמות, לא בשימוש, ולא מקושרים מ־`index.html`.

## הרצה

פתיחת `index.html` בדפדפן, או כניסה ל־https://truetailor-app.github.io/TrueTailor-CV/

בשימוש ראשון נדרשת הדבקת מפתח Gemini API. המפתח נשמר ב־`localStorage` לפי מקור הקובץ, כלומר פתיחה של הקובץ מתיקייה אחרת דורשת הדבקה מחדש.

נדרשת גישה לרשת בטעינה ראשונה: הקובץ מושך Tailwind, גופנים Heebo ו־Assistant, JSZip, Mammoth ו־pdf.js מ־CDN.

## פרסום גרסה חדשה

מתוך תיקיית העבודה המקומית:

```
update_site.bat TrueTailor_CV_v35_7.html
```

בלי ארגומנט הסקריפט בוחר את הקובץ `TrueTailor_CV_v*.html` העדכני ביותר לפי תאריך שינוי ומבקש אישור.

לפני שהוא נוגע ב־`index.html` הוא מוודא ש־git זמין, שהתיקייה היא מאגר git, שקובץ המקור גדול מ־100KB, שיש בו `</html>` סוגר ושניתן לקרוא ממנו `TT_VERSION`. כשל באחת מהבדיקות עוצר בלי לשנות דבר.

אם `origin` עדיין מצביע על המאגר הישן, הסקריפט מציע לתקן אותו במקום ומחכה לאישור. סירוב עוצר בלי לשנות את ה־remote.

## עבודה על הקוד

לפני כל משימה טכנית: קריאת תיק הפרויקט. סעיף 2 בתיק מגדיר את עקרונות היושרה של המוצר, וסעיף 6 מפרט את מנגנוני ההגנה שיושבים בקוד ולא בפרומפט.

שני כללים שנשברו בעבר וכתובים בתיק:

1. סדר גיליונות הסגנון. ה־CDN של Tailwind מזריק את הגיליון שלו ל־head בזמן ריצה, אחרי בלוק ה־style של הקובץ. כלל שחייב לנצח נכתב כ־`html body` או נושא מחלקה.
2. `.tt-page`, משתני התבניות וצינור הייצוא מזינים יחד את התצוגה, את ה־Word ואת ה־PDF. שינוי באחד מפצל את שלושתם.

בכל מסירה: עדכון `TT_VERSION` ועדכון סעיף 9 בתיק.

## מצב בדיקה

מה שנבדק: `index.html` הוא `v35.6` ומסתיים בתגית סגירה תקינה. אין במאגר אף הפניה לכתובת או לשם משתמש ישנים. `update_site.bat` נבדק ברמת הלוגיקה מול מאגר git אמיתי, כולל קלטים פגומים בכוונה (קובץ קטוע, קובץ בלי `TT_VERSION`, remote שגוי) — כולם נעצרו בלי לשנות את `index.html`. תיקון ה־remote נבדק בשני הכיוונים: אישור מתקן וממשיך, סירוב משאיר את ה־remote כפי שהיה.

מה שלא נבדק: ריצה מול Gemini API, ייצוא Word וייצוא PDF. לפי סעיף 10 בתיק אלה לא נבדקו מאז v25.8. כמו כן `update_site.bat` עצמו לא הורץ בפועל תחת cmd.exe.
